# Модель угроз РАЛМАСТЕР

Дата актуализации: 2026-11-08.

## 1. Область и архитектура

В область входят публичный сайт `ral-master.ru`, административная панель
1С-Битрикс, каталог и корзина, формы заявок с вложениями, почтовая отправка,
MySQL, пользовательские загрузки и интеграции шаблона Aspro Allcorp2.

Фактический production размещён на хостинге Beget. Docker Compose и Apache из
репозитория используются только для воспроизводимой локальной и
production-like проверки; это не описание production-инфраструктуры Beget.

Основной поток данных:

1. браузер посетителя → DNS/TLS/HTTP Beget;
2. веб-сервер Beget → PHP/1С-Битрикс и шаблон Aspro;
3. PHP → MySQL, файловое хранилище `upload/`, почтовая подсистема;
4. администратор → `/bitrix/admin/` → изменение контента и конфигурации;
5. внешние сервисы → карты, социальные сети, CDN и почтовая инфраструктура.

## 2. Активы

- контактные и персональные данные из форм;
- прикреплённые чертежи, фотографии и офисные документы;
- учётные записи и сессии администраторов;
- конфигурация Bitrix, лицензия и ключи внешних интеграций;
- база данных каталога, заказов и контента;
- доступность сайта, формы и почтовой доставки;
- исходный код, история Git, резервные копии и журналы;
- репутация домена и целостность публикуемого контента.

## 3. Роли и границы доверия

| Роль | Уровень доверия | Основные возможности |
| --- | --- | --- |
| Анонимный посетитель | недоверенный | просмотр страниц, поиск, корзина, формы, CAPTCHA, загрузка вложений |
| Покупатель/пользователь | ограниченный | сессия, корзина, возможная регистрация и личный кабинет |
| Контент-менеджер | привилегированный | контент, файлы, инфоблоки |
| Администратор Bitrix | критический | модули, пользователи, настройки, PHP-области |
| Beget/почтовый провайдер | внешняя доверенная сторона | TLS, сеть, WAF/anti-DDoS при наличии, SMTP, backups |
| Сторонний JS/API | внешняя недоверенная зависимость | код/данные в браузере и внешние запросы |

Границы доверия проходят между браузером и HTTP, PHP и MySQL, приложением и
`upload/`, Bitrix и сторонними модулями, сайтом и почтовым/внешним сервисом,
рабочей станцией разработчика и Git/backup-хранилищем.

## 4. Ключевые сценарии угроз

### 4.1 Идентификация и аутентификация

- credential stuffing и перебор паролей администратора;
- захват сессии через слабые cookie/TTL или сохранённую сессию;
- отсутствие обязательного MFA для привилегированных пользователей;
- массовая регистрация и восстановление пароля без CAPTCHA/rate limit;
- утечка существования учётной записи через различающиеся ответы.

### 4.2 Авторизация и CSRF

- изменение настроек, корзины, CAPTCHA или AJAX-компонентов запросом с чужого
  сайта;
- прямой вызов административного обработчика без проверки прав;
- доверие к параметрам компонента или имени глобального фильтра из запроса.

### 4.3 Ввод, вывод и редиректы

- XSS через город, URL, data-атрибуты, подписи и HTML-синк;
- open redirect через `backurl` или региональный домен;
- object injection/DoS через PHP serialized payload;
- обход валидации двойным URL-кодированием, `//host` или backslash;
- раскрытие внутренних путей через PHP warning/debug output.

### 4.4 Файлы

- web shell через двойное расширение или серверный handler;
- SVG/HTML active content и MIME spoofing;
- ZIP/OLE/polyglot, чрезмерный размер, большое число файлов;
- чтение публично доступного вложения без бизнес-авторизации;
- `.htaccess` или executable в каталоге загрузок.

### 4.5 Секреты и артефакты

- публикация `.env`, SQL dump, log, backup, Docker/deploy-конфигурации;
- секрет в Git history, архиве или ignored-файле рабочей станции;
- повторное использование уже скомпрометированного API-токена;
- раскрытие версии сервера, PHP или модуля.

### 4.6 Доступность и злоупотребления

- volumetric DDoS на сеть Beget;
- slow HTTP, исчерпание PHP workers/DB connections;
- частые CAPTCHA refresh, AJAX-каталог, поиск и тяжёлые формы;
- большие загрузки и decompression/resource exhaustion;
- бот-спам форм и почтовой подсистемы;
- отказ DNS/TLS/Beget как единой внешней точки отказа.

## 5. Реализованные контрмеры

- allowlist same-origin путей для редиректов и конфигурируемых хостов;
- POST + Bitrix sessid для изменяющих state обработчиков;
- проверка прав администратора для сохранения настроек;
- отключён CAPTCHA answer oracle и добавлен session rate limit refresh;
- строгие размеры/типы/глубина AJAX payload и запрет PHP object classes;
- allowlist вложений, сигнатуры/MIME, размеры и проверка изображений/Office;
- запрет исполнения и directory listing в `upload/`;
- запрет публикации dotfiles, backups, SQL/log/env/deploy-артефактов;
- `nosniff`, anti-framing, Referrer/Permissions Policy, `no-store` для
  чувствительных маршрутов;
- локальный Apache: скрытие версии, TRACE off, request timeouts/limits;
- production-like Compose: обязательные пароли, loopback binding,
  `no-new-privileges`, resource/pid limits и read-only код;
- PHP production-like: errors off, strict cookies, `allow_url_include=Off`,
  upload/execution/memory limits;
- автоматические security-регрессионные тесты.

## 6. Остаточные риски и владелец

| Риск | Владелец | Приоритет |
| --- | --- | --- |
| Устаревшие `main` и `security` Bitrix | владелец лицензии/администратор Bitrix | критический до релиза |
| WAF, anti-DDoS, rate limit, логи и backups Beget не подтверждены | владелец хостинга | высокий |
| В локальной копии не включены MFA, event log, proactive filter, CAPTCHA регистрации/восстановления | администратор Bitrix | высокий |
| Ранее опубликованный Instagram token необходимо отозвать | владелец интеграции | высокий |
| Полный CSP несовместим с legacy inline JS без поэтапного report-only внедрения | разработчик + QA | средний |
| SQL dump/log/архивы присутствуют локально вне Git | владелец рабочей станции | средний |
| Антивирус/CDR вложений отсутствует | владелец инфраструктуры | средний |
| DMARC не опубликован; DKIM требует проверки в панели Beget | владелец домена/почты | средний |

## 7. Security gates перед релизом

1. Обновить Bitrix и Aspro в staging, затем повторить функциональную и
   security-регрессию.
2. Включить MFA для администраторов, event log, proactive filter/WAF,
   CAPTCHA/anti-bot для регистрации и восстановления.
3. Отозвать legacy Instagram token и проверить остальные секреты в кабинетах.
4. Подтвердить у Beget TLS, backups/restore, WAF/anti-DDoS, rate limits и
   доступ к журналам.
5. Восстановить доступность `https://ral-master.ru/` и проверить заголовки/TLS.
   HSTS включать только после успешной проверки HTTPS всех нужных поддоменов.
6. Настроить DMARC (сначала monitoring policy) и подтвердить DKIM.
7. Выполнить полный smoke/functional тест после переноса на Beget.

## 8. Допущения

- настройки локальной восстановленной БД считаются снимком, а не гарантией
  текущего production;
- активное сканирование, нагрузочные тесты и эксплуатация уязвимостей на
  production не выполнялись;
- защита уровня сети и хостинга не может быть доказана из исходного кода.

Базовый стандарт проверки: OWASP ASVS 4.0.3 Level 2, OWASP File Upload и
Denial of Service Cheat Sheets.
